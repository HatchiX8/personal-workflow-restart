# Refactor Router Skill

## 適用情境

當任務明確要求重構、整理命名、拆分函式、調整分層、移除重複邏輯時啟用。

若任務是新增功能、修 Bug、調整 API 行為，不得自行視為重構。

---

## 重構模式判定

執行前先判定模式：

- Node.js Backend Refactor → node-backend-refactor.md
- Python Backend Refactor → python-backend-refactor.md 目前尚未支援
- Frontend Refactor → frontend-refactor.md 目前尚未支援

若同時涉及多種模式，必須停止並建議拆分任務。

若找不到對應 Skill，必須停止，不得自行推測規則。

---

## 共用限制

- 每次重構必須有一個明確的主要目標
- 其餘修改只能服務於該主要目標
- 不得改變既有功能行為
- 不得改變 API 路徑
- 不得改變 Request / Response 結構
- 不得新增套件依賴，除非使用者要求
- 小範圍重構可以直接執行
- 大範圍重構必須先停止並回報拆分建議
- 不得自行將小範圍重構升級為大範圍重構

## 重構範圍判定

重構前必須先判斷本次任務屬於小範圍重構或大範圍重構。

若同時符合小範圍與大範圍條件，以大範圍重構判定為準。

### 小範圍重構

符合以下任一範圍，且未觸發大範圍重構條件時，視為小範圍重構：

- 只修改單一函式
- 只修改單一檔案
- 只整理單一 API 的 controller / service / repository 流程
- 只整理單一模組內的命名
- 只抽出單一模組內的 mapper / formatter / calculator

小範圍重構必須符合：

- 不改變 API path
- 不改變 Request / Response
- 不改變資料庫 schema
- 不新增套件依賴

小範圍重構可以在完成執行前檢查後直接執行。

### 大範圍重構

符合以下任一情況時，視為大範圍重構：

- 涉及多支 API
- 涉及多個模組
- 涉及跨層架構調整
- 涉及資料庫 schema
- 涉及 Request / Response 結構變更
- 涉及新增套件依賴
- 涉及路由規則調整
- 涉及共用架構設計
- 涉及全域資料夾或共用工具建立
- 需要同時調整前端與後端
- 需要同時調整 Node.js 與 Python Service

大範圍重構不得直接執行。

必須先停止並回報：

- 判定為大範圍重構的原因
- 可能影響範圍
- 建議拆分順序

## 執行前檢查

先執行：

git status

若有未提交變更，先回報，不得覆蓋。

---

## 執行後要求

重構完成後必須回報：

- 使用的重構模式
- 修改檔案
- 是否改變功能行為
- 是否改變 API
- 是否新增依賴
- 驗證方式與結果
