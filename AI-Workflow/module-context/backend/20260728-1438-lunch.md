## Engineer Summary

`lunch` 模組負責午餐餐廳管理、訂餐活動建立與刪除、活動內個人訂餐明細查詢與維護。API 由 `src/routes/router.js` 掛到 `/api/lunch`，再由 `src/routes/lunch.routes.js` 定義各子路由，controller 建立 DTO 後交給 service，service 主要包裝錯誤，repository 直接使用 Prisma 存取 `Lunch`、`LunchRestaurant`、`OrderLunch`。

後續修改最常碰到的入口是 `lunch.routes.js`、`lunch.controller.js`、`lunch.dto.js` 與 `lunch.repository.js`。最需要小心的是 request body 欄位與 DTO 轉換，例如餐廳使用 `restaurant`、`depiction`、`phone` 轉成 DB 欄位，訂餐活動使用 `restaurantId`、`userId` 轉成 `lunchId`、`employeeId`。

本 context 狀態為 READY；可支援後續 agent 在既有邊界內修改，但認證 middleware、validation 與 Swagger 描述是否一致仍需人工確認。
