# Project Structure Skill

本文件是專案結構規則範本。

工程師可依每個專案的實際資料夾結構、模組責任與依賴邊界調整本文件。

## 專案結構

工程師可在此定義本專案的主要資料夾用途，避免 Agent 每次修改時自行判斷模組邊界。

範例：

- `modules/`：放置業務功能模組
- `stores/`：放置 Pinia stores
- `components/`：放置共用 UI components
- `composables/`：放置可重用的 Composition API logic
- `services/`：放置 API client 或 service logic
- `types/`：放置共用型別

## 適用情境

當任務涉及以下情境時，Agent 必須讀取本 skill：

- 新增、移動或拆分檔案
- 刪除檔案或資料夾
- 新增資料夾或模組
- 調整 import direction
- 改變專案分層
- 新增跨模組共用工具

## 使用限制

- 本 skill 僅補充專案客製結構規則，不取代規則載入流程
- 本 skill 可覆蓋通用任務類型規則，但不得違反 `AI-Workflow/roles/developer/restrictions.md`
- 不得因「最佳實踐」主動改變既有資料夾結構
- 不得在未確認責任邊界前新增共用層、抽象層或跨模組依賴
- 若本文件尚未依專案填寫，Agent 不得將範本內容視為實際專案規則

## 操作流程

1. 先確認本次任務是否真的需要新增、移動、刪除、拆分檔案或調整 import。
2. 讀取既有專案目錄與同類型檔案位置。
3. 依本專案已填寫的結構規則判斷檔案放置位置、模組責任與依賴方向。
4. 若本文件未定義對應規則，優先維持既有結構並採用最小影響修改。
5. 若任務必須依賴未定義的結構規則才能完成，停止修改並回報需要工程師補充本 skill。

## 驗證方式

任務完成後，Agent 必須檢查：

- 是否只修改本次任務必要範圍
- 是否符合既有資料夾結構與命名習慣
- 是否破壞既有 import path 或 public API
- 是否產生跨層依賴、重複商業邏輯或不必要抽象
- 是否依修改範圍執行對應的 lint、typecheck、build 或 test

## 完成輸出要求

任務完成回報時，Agent 必須說明：

- 新增、移動、刪除或拆分了哪些檔案
- 檔案放置位置的依據
- 是否有調整 import direction
- 已執行的驗證
- 是否有需要工程師補充或確認的結構規則
