# Core Rules

- 優先考慮可維護性
- 優先考慮可閱讀性
- 優先考慮資料流穩定性
- 不允許破壞既有資料流
- 所有功能都應具備明確責任邊界
- UI 與商業邏輯必須分離
- 優先維持既有架構一致性
- 優先採用最小影響修改
- 避免不必要的抽象化
- 避免重複商業邏輯
- 模組應保持單一職責
- 優先使用可組合設計

## 穩定性原則

- 優先維持既有可理解的命名、結構與資料流
- 不得僅因個人偏好進行局部命名調整
- 若專案已有一致性規範，允許為維持整體一致性進行必要調整
- 命名修改需具有明確的可讀性、語意一致性或維護性改善理由
- 應避免低價值、高修改成本的命名重構
