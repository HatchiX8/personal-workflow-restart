# 任務日誌蒐集與關聯

## 篩選日誌

1. 以 UTF-8 讀取 Workflow Root 的 `agent-workspaces/task-journals/` 下可存取 Markdown 檔。
2. 只採用 YAML frontmatter 中可解析且落在 `[start, end)` 的 `completed_at`。不得以檔案建立、修改或目錄時間判定是否納入。
3. 收集 `thread_id`、`mode`、`project`、`role`、`skills`、`status` 與正文中的客觀結果、驗證、未完成項目和阻礙。缺欄位、時間無法解析或內容不足時，保留限制，不猜測。

## 補充與去重

- 日誌資訊不足時，才可用其 `thread_id` 唯讀讀取同一個可取得的 Codex thread，補充必要的範圍、結果或明確決策；若無法讀取，標示限制。
- 每份任務日誌與其為補充而讀取的同一 thread 只構成一個事件。先以日誌為主，thread 只補上日誌沒有的已確認事實，不能重複列為另一個成果或改善事項。
- 沒有日誌的對話事件以 thread ID、Turn／訊息時間與主題去重；相同事件在多個 Turn 出現時合併為單一事件並保留最直接的證據。

## 跨來源關聯

ChatGPT 討論與 Codex 任務同時符合下列條件時，才可關聯為同一事件或前後因果：

- 專案或工作對象一致；
- 主題或任務目標一致；
- 時間順序與範圍合理；
- 有明確、可讀取的決策、thread ID 或其他直接證據支持連結。

只有名稱相似、時間接近、推測使用者意圖或一般主題相同，都不足以強制關聯。證據不足時保留分開事件，並避免暗示因果關係。
