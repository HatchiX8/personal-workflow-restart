# 週報格式與寫作規則

每份報告使用 UTF-8 Markdown，並以可追溯、客觀且精簡的方式填寫。每個重點都要附「證據」與「影響」：正文證據只顯示可讀的來源名稱、時間與短代碼，完整識別資訊集中放在報告末尾的「證據索引」；影響只描述已觀察到或合理直接可見的工作影響，不做人格、情緒或動機判斷。

```markdown
---
report_start: "[start]"
report_end: "[end]"
generated_at: "[generated_at]"
---
```

- `report_start`、`report_end` 與 `generated_at` 必須使用含 `+08:00` offset 的標準 ISO 8601 時間並保留 `T`。`report_end` 是保存期限清理的唯一時間依據，不得以檔名或檔案修改時間替代。
- YAML frontmatter 以外，所有供人閱讀的日期時間都使用 `YYYY-MM-DD HH:mm` 或同樣以半形空格分隔日期與時間的格式，不顯示 `T`；時區不明時不得自行補造。
- 正文不得直接顯示完整 thread ID、turn ID 或其他 UUID。每項證據使用 `E01`、`E02` 等報告內唯一短代碼，並在「證據索引」保存完整追溯資訊。
- 「證據索引」只列正文實際引用的證據。ChatGPT 證據保存來源名稱、完整 thread ID、必要的 turn ID 與時間；任務日誌證據保存可讀名稱、完整日誌檔名與 `completed_at`。同一證據被多處使用時沿用同一短代碼，不重複建立索引。
- Turn ID 僅在可取得且有助於定位特定訊息時保存；無法取得或無實際定位用途時填「未提供」，不得補造。
- 範本中的所有區塊都必須保留。「重要決策與成果」、「老闆做得好／可改善」、「AI 員工做得好／可改善」、「團隊流程改善」、「未完成與待決策」與「下週行動」各自最多 3 個不重複重點；沒有證據時不建立條目，並在該區塊寫「無足夠證據」。
- 「做得好」只記錄已證實有助於目標、範圍、決策或交付的具體行為；「可改善」只記錄有具體證據的資訊缺口、重工、阻礙、延遲或可避免的流程摩擦。
- 同一事件只能在最能說明它的主要區塊完整敘述。其他區塊若確有必要提及，只能簡短交叉參照，不能重複計數或把它視為獨立證據。
- 報告只提出下週行動或待決策；不得自行改寫長期規則、Workflow、角色規則或其他 Skill。
