# Developer 驗證與自我檢查

產生修改後，必須依序檢查以下項目。唯讀分析的證據、推論與未確認事項由 `workflow.md` 的唯讀分析流程處理，不進入本文件的修改驗證。

## 執行驗證

依 Project Config、本次修改範圍與適用 Skills 執行：

- 修改 TypeScript 時執行專案提供的 typecheck。
- 專案有 lint 且修改相關程式碼時執行 lint。
- 涉及可建置程式碼或設定時執行 build。
- 執行本次修改直接相關的測試。

若因環境限制無法執行，必須在輸出中標示未執行項目、原因與建議工程師執行的指令。

## Scope

- 是否僅修改本次任務相關範圍
- 是否修改無關模組
- 是否刪除既有功能
- 是否變更既有 public API
- 是否主動重新命名檔案或移動資料夾結構

## Data Flow

- 是否破壞既有資料流
- 是否繞過既有狀態或資料管理流程
- 是否引入隱式共享狀態

## Architecture

- 是否產生重複商業邏輯
- 是否出現跨層依賴
- 是否有過度耦合
- 是否有不必要的抽象化
- 是否違反既有架構風格

## Code Quality

- 是否有未使用 import
- 是否有未使用變數
- 是否有重複程式碼
- 是否有過深的條件分支
- 是否有難以理解的命名

## Validation

- 是否已執行本專案對應的 lint / typecheck / build / test
- 若無法執行驗證，是否已在輸出結果中明確說明原因
