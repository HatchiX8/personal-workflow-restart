# Developer Tooling Target Skill

## 適用範圍

- CLI 工具。
- 檔案整理、轉換與批次處理。
- 資料匯入、匯出與清洗。
- 開發流程自動化。
- 本機維運或檢查腳本。
- 將一次性程式整理成可重複執行工具。

## 設計規則

- 工具必須有明確的輸入、處理與輸出邊界。
- 預設行為必須保守，避免直接覆蓋或刪除資料。
- 會修改檔案或外部狀態的工具，應優先支援 dry-run。
- 批次處理應清楚回報成功、失敗與略過項目。
- 不得硬編碼環境路徑、帳密、token 或專案絕對路徑。
- 不得把一次性假設寫成未說明的隱藏規則。

## 檔案操作

- 寫入、覆蓋、刪除或搬移前，確認目標路徑來自明確輸入或已驗證的安全推導。
- 批次修改前，先確認將受影響的檔案範圍。
- 破壞性操作需提供確認機制或 dry-run。
- 除非任務明確要求，輸出檔案不得覆蓋原始資料。
- 文字檔案預設以 UTF-8 讀寫；專案另有明確編碼規則時依專案規則。

## CLI 輸出

- 成功時輸出簡潔摘要。
- 失敗時輸出原因與可採取的下一步。
- 批次任務輸出 processed、created、updated、skipped、failed 等統計資訊。
- 不得輸出 token、password、secret 或完整憑證內容。

## 結構

簡單工具可維持單一檔案。開始包含多個責任時，依既有專案風格區分：

- CLI entry：處理參數與輸出。
- Core logic：處理主要邏輯。
- IO layer：處理檔案、網路或外部系統。

不得只為符合通用分層而主動拆分仍然清楚的簡單工具。

## 驗證

- 執行專案設定中與修改相關的 lint、typecheck、test 或 build。
- 對主要命令執行不改變外部狀態的最小 smoke test。
- 工具會修改資料時優先驗證 dry-run。
- 無法執行驗證時，回報原因與建議手動執行的指令。

## 完成檢查

- 輸入、處理與輸出邊界是否清楚。
- 是否避免硬編碼環境資訊或敏感資訊。
- 破壞性操作是否具有 dry-run 或確認機制。
- 錯誤與批次結果是否清楚回報。
- 是否完成與修改相關的語法檢查、測試或 smoke test。
